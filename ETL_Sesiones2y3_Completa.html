¿Qué es ETL y por qué importa?

El fundamento de todo análisis de datos

ETL son las siglas de Extract, Transform, Load — el proceso mediante el cual los datos pasan de sus fuentes originales a un estado utilizable para el análisis y la toma de decisiones.

📥
Extract (Extraer)

Cargar datos desde la fuente original: archivos Excel, bases de datos, APIs, etc. Sin tocar ni modificar nada.

🔧
Transform (Transformar)

Limpiar, corregir, estandarizar y enriquecer los datos. Aquí está el 80% del trabajo de un Data Scientist.

📤
Load (Cargar)

Guardar el dataset limpio en el destino final: un data warehouse, CSV limpio, base de datos analítica.

Auditoría Inicial

Reporte de calidad completo — describe el estado, no propone soluciones

La auditoría es el primer paso del ETL: observar antes de actuar. Genera un reporte que describe el estado actual de los datos sin modificar nada.

🧒 Como para un niño de 8 años

Antes de limpiar tu cuarto, primero lo revisas: ¿cuántos juguetes hay?, ¿cuántos están rotos?, ¿hay calcetines en el suelo? No limpias nada todavía — solo anotas lo que ves. Eso es una auditoría.

def auditar_dataframe(df, nombre):
    """
    Genera un reporte de calidad completo sobre cualquier DataFrame.
    No revela soluciones — solo describe el estado actual del dato.
    """
    print("=" * 60)
    print(f"  REPORTE DE AUDITORÍA — {nombre}")
    print("=" * 60)
    print(f"\n  Dimensiones : {df.shape[0]:,} filas × {df.shape[1]} columnas")
    print(f"  Memoria     : {df.memory_usage(deep=True).sum() / 1024**2:.2f} MB")

    print("\n  ── TIPOS DE DATOS ──────────────────────────────────")
    for col in df.columns:
        dtype  = str(df[col].dtype)
        nulos  = df[col].isnull().sum()
        pct    = nulos / len(df) * 100
        unicos = df[col].nunique()
        flag   = " ⚠️" if nulos > 0 else ""
        print(f"  {col:<22} {dtype:<12} nulos: {nulos:>5} ({pct:>4.1f}%)  únicos: {unicos:>6}{flag}")

    print(f"\n  ── DUPLICADOS ──────────────────────────────────────")
    dups = df.duplicated().sum()
    print(f"  Filas duplicadas exactas : {dups:,} ({dups/len(df)*100:.2f}%)")

    print(f"\n  ── ESTADÍSTICAS NUMÉRICAS ──────────────────────────")
    cols_num = df.select_dtypes(include='number').columns
    if len(cols_num) > 0:
        print(df[cols_num].describe().round(2).to_string())

df[cols_num].describe()Calcula automáticamente: count, mean, std, min, 25%, 50%, 75%, max para cada columna numérica. Es el punto de partida para detectar outliers y rangos sospechosos.

def auditar_categoricas(df, columnas):
    """
    Muestra la distribución de frecuencias de columnas categóricas.
    Útil para detectar inconsistencias de texto que las estadísticas
    numéricas no pueden revelar.
    """
    for col in columnas:
        print(f"\n{'─'*50}")
        print(f"  Columna: '{col}'")
        conteo = df[col].value_counts(dropna=False)  # incluye NaN
        for valor, n in conteo.items():
            pct   = n / len(df) * 100
            barra = '█' * int(pct / 2)            # barra visual proporcional
            label = str(valor) if pd.notna(valor) else 'NaN (nulo)'
            print(f"  {label:<25} {n:>6,}  {pct:>5.1f}%  {barra}")

Auditoría de rangos numéricos

Un dato puede ser técnicamente válido pero contextualmente imposible

🧒 Como para un niño de 8 años

Si en tu examen sacaste "150 sobre 100", técnicamente es un número que Python puede guardar sin problema. Pero contextualmente es imposible — la nota máxima es 100. Los rangos de negocio son esas reglas que dice "esto no puede ser así aunque Python no se queje".

def auditar_rangos(df, columnas_reglas):
    """
    Verifica si los valores numéricos están dentro de rangos esperados.
    Las reglas de negocio las defines tú — no el sistema.

    columnas_reglas: dict con {'columna': (min_esperado, max_esperado)}
    """
    print("AUDITORÍA DE RANGOS DE NEGOCIO\n")
    for col, (minimo, maximo) in columnas_reglas.items():
        fuera = df[(df[col] < minimo) | (df[col] > maximo)]
        pct   = len(fuera) / len(df) * 100
        estado = "⚠️  REVISAR" if len(fuera) > 0 else "✅ OK"
        print(f"  {col:<22} rango esperado [{minimo:>8,.0f} – {maximo:>10,.0f}]")
        print(f"  {'':22} fuera de rango: {len(fuera):>6,} filas ({pct:.2f}%)  {estado}")
        if len(fuera) > 0:
            print(f"  {'':22} max encontrado: {df[col].max():>10,.2f}")

reglas = {

    'total_venta'     : (0.50, 5000),   # venta mínima 50 ctvs, máxima $5,000

Estandarización preliminar de strings

Capitalización uniforme como base para la limpieza profunda

def estandarizar_capitalización(df, columnas):
    """
    Aplica .str.strip() y .str.title() a columnas de texto.
    - strip(): elimina espacios al inicio y al final
    - title(): primera letra de cada palabra en mayúscula
    """
    for col in columnas:
        original = df[col].copy()
        df[col]  = df[col].str.strip().str.title()
        cambios  = (original != df[col]).sum()
        print(f"  {col:<20} → {cambios:>4} valores modificados")

estandarizar_capitalización(fv, ['canal', 'metodo_pago'])
.str.strip()Elimina espacios en blanco, tabs o saltos de línea al inicio y al final del texto. " Efectivo " → "Efectivo". Un espacio invisible puede hacer que dos valores iguales no coincidan en un JOIN.
.str.title()Convierte la primera letra de cada palabra a mayúscula y el resto a minúscula. "EFECTIVO" → "Efectivo", "efectivo" → "Efectivo". Esto unifica la capitalización, pero no soluciona sinónimos como "T.Debito" vs "Tarjeta Débito".
(original != df[col]).sum()Compara la columna original con la columna modificada elemento por elemento (True donde cambiaron), y suma los True para contar cuántas filas fueron modificadas.

3. Tratamiento de Valores Nulos

Los 3 mecanismos de ausencia: MCAR, MAR, MNAR

📖
Statistical Analysis with Missing Data — Little & Rubin (Wiley, 3ª ed. 2019)
Roderick J.A. Little · Donald B. Rubin
"The mechanism by which data come to be missing is a crucial factor in choosing the right analysis. Missing data that are Missing Completely At Random (MCAR), Missing At Random (MAR), or Missing Not At Random (MNAR) require fundamentally different treatments."

La estadística moderna clasifica los datos faltantes en tres categorías. La decisión de qué hacer con un nulo depende de por qué existe ese nulo.

🎲
MCAR — Missing Completely At Random

El dato falta por causas totalmente aleatorias, sin relación con ninguna variable. Puedes imputar o eliminar sin sesgar el análisis.

Ejemplo: Corte de luz de 2 minutos → 15 transacciones sin método de pago al azar.

🔗
MAR — Missing At Random

El dato falta por razones relacionadas con otras variables observables, no con el valor faltante en sí.

Ejemplo: Clientes que pagan en efectivo tienden a no registrar el canal de venta.

🚨
MNAR — Missing Not At Random

El dato falta por razones relacionadas con el propio valor no observado. El más peligroso — requiere criterio de negocio.

Ejemplo: Transacciones de alto monto deliberadamente sin método de pago.

🧒 Como para un niño de 8 años

MCAR: Tu perro comió aleatoriamente 5 hojas de tu tarea — no importa cuáles, fue al azar.

4. Outliers / Valores Atípicos

4.1 — Qué son · 4.2 — Métodos · 4.3 — Impacto real en el dataset

Un outlier (valor atípico) es una observación que se aleja significativamente del resto. Hay dos tipos fundamentales que debes distinguir antes de actuar:

🐛
Outlier por Error

Es un error de captura, sistema o proceso. El dato está mal desde el origen.

Ejemplo en el dataset: total_venta = $83,850 cuando el máximo real es ~$3,146. El sistema multiplicó el valor por 8-15x accidentalmente.

🦄
Outlier Real (evento genuino)

El dato es correcto — ese evento fue inusualmente extremo pero ocurrió.

Ejemplo: Una empresa compró 200 unidades en una sola orden corporativa. Raro, pero real.

🚨
Regla crítica del notebook: "Nunca elimines un outlier sin primero determinar si es un error o un evento real. Eliminar eventos reales extremos sesga el análisis y oculta información valiosa de negocio."

4.2

Métodos de detección de outliers

IQR de Tukey y Z-Score — los dos métodos del curso

Método 1 — Regla IQR (Criterio de Tukey) ← el que usamos

🧒 Como para un niño de 8 años

Ordena tus calificaciones de menor a mayor: 60, 70, 75, 80, 82, 85, 90, 95. El Q1 es la nota en el 25% de la lista (~70). El Q3 es la nota en el 75% (~90). El IQR es la distancia entre Q3 y Q1 = 20. Ahora cualquier nota menor a 70-(1.5×20)=40 o mayor a 90+(1.5×20)=120 es sospechosa. Una nota de 120 en un examen de 100 puntos — eso es un outlier.

Q1 = Percentil 25   |   Q3 = Percentil 75   |   IQR = Q3 − Q1

Límite inferior = Q1 − 1.5 × IQR
Límite superior = Q3 + 1.5 × IQR

Todo valor fuera de estos límites → candidato a outlier
💡
¿Por qué exactamente 1.5? Tukey demostró matemáticamente que con ese factor, en una distribución perfectamente normal, solo el 0.7% de los datos caen fuera de los límites. Eso los hace genuinamente extremos. Con factor 3.0, solo el 0.0001% queda afuera — para detectar outliers ultra severos.

Método 2 — Z-Score (Puntaje Z)

Z = (valor − media) / desviación estándar

Si |Z| > 3 → outlier (cubre el 99.7% de una distribución normal)
CriterioIQR de Tukey ← usamosZ-Score

def detectar_outliers_iqr(df, columnas, factor=1.5):
    """
    Detecta outliers usando la Regla IQR de Tukey.
    Retorna un DataFrame con el resumen por columna.

    factor=1.5 → outliers moderados (Tukey estándar)
    factor=3.0 → outliers extremos (solo casos severos)
    """
    resultados = []
    for col in columnas:
        serie   = df[col].dropna()            # ignorar nulos para el cálculo
        q1      = serie.quantile(0.25)
        q3      = serie.quantile(0.75)
        iqr     = q3 - q1
        lim_inf = q1 - factor * iqr           # límite por abajo
        lim_sup = q3 + factor * iqr           # límite por arriba

        # True para cada fila que está FUERA de los límites (en cualquier extremo)
        mask_out   = (df[col] < lim_inf) | (df[col] > lim_sup)
        n_outliers = mask_out.sum()

        resultados.append({
            'columna'     : col,
            'Q1'          : round(q1, 2),
            'Q3'          : round(q3, 2),
            'IQR'         : round(iqr, 2),
            'lim_inferior': round(lim_inf, 2),
            'lim_superior': round(lim_sup, 2),
            'outliers'    : n_outliers,
            'pct_%'       : round(n_outliers / len(df) * 100, 3),
            'max_valor'   : round(df[col].max(), 2),
        })
    return pd.DataFrame(resultados).sort_values('outliers', ascending=False)

5.2 — Decisión de tratamiento: Winsorización

Recortar al límite en vez de eliminar la fila completa

🧒 Como para un niño de 8 años

Tienes una regla que mide de 0 a 30 cm. Alguien midió algo que dio "500 cm" — claramente un error. En vez de tirar esa hoja de datos, recortas el valor al máximo de tu regla: 30 cm. La medición sigue en el dataset, solo con un valor razonable. Eso es Winsorizar: recortar al límite, no eliminar.

✂️
Winsorización ← lo que hacemos

Reemplazamos el valor extremo con el límite IQR. La fila se conserva. No perdemos ninguna transacción.

🗑️
Eliminación ← lo que NO hacemos

Perdemos filas completas. Introduce sesgo en reportes de volumen. El total de ventas procesadas quedaría incompleto.

def winsorizat_iqr(df, columna, factor=1.5):
    """
    Aplica Winsorización usando los límites IQR.
    Reemplaza valores fuera de los límites con el límite correspondiente.
    No elimina filas — preserva todas las transacciones.
    """
    q1      = df[columna].quantile(0.25)
    q3      = df[columna].quantile(0.75)
    iqr     = q3 - q1
    lim_inf = q1 - factor * iqr
    lim_sup = q3 + factor * iqr

    n_inf = (df[columna] < lim_inf).sum()   # cuántos serán recortados abajo
    n_sup = (df[columna] > lim_sup).sum()   # cuántos serán recortados arriba

    # ★ .clip() es el corazón de la Winsorización:
    # → Si valor < lim_inf → queda en lim_inf
    # → Si valor > lim_sup → queda en lim_sup
    # → Si está dentro del rango → no cambia
    df[columna] = df[columna].clip(lower=lim_inf, upper=lim_sup)

    print(f"  '{columna}':")
    print(f"    Límite superior: ${lim_sup:>10,.2f} → {n_sup} valores recortados")
    print(f"    Nuevo máximo  : ${df[columna].max():>10,.2f}")
    print(f"    Nueva media   : ${df[columna].mean():>10,.2f}")
    return df

        lambda x: mapa_reemplazos.get(x, x) if pd.notna(x) else x
    )
    n_cambios = (df[columna] != cambios).sum()
    df[columna] = cambios
    n_despues = df[columna].nunique()

    print(f"  '{columna}': {n_antes} → {n_despues} únicos, {n_cambios:,} registros modificados")
    return df

6.2 — Duplicados: detección y eliminación

Los 3 tipos de duplicados en datos transaccionales

🔴 Duplicado exacto

Todas las columnas son idénticas. Mismo ID, mismo valor, mismo todo. Error claro del sistema.

🟡 Duplicado de clave

El ID es el mismo pero algún campo varía. Difícil de detectar. Requiere investigar cuál es el correcto.

🟢 Duplicado de negocio

Diferentes IDs pero misma transacción procesada dos veces por el sistema.

6.3 — Violación de dominio

El valor existe, no es nulo, no es duplicado — pero no pertenece a los valores válidos

🧒 Como para un niño de 8 años

Un examen de opción múltiple tiene respuestas: A, B, C o D. Si alguien contesta "E" — esa respuesta existe, no está en blanco, pero no está en el conjunto de opciones válidas. Eso es una violación de dominio.

# Definir los valores válidos por columna según las reglas del negocio
dominios = {

7. Integridad Referencial y JOINs de Validación

¿Cada venta apunta a un cliente, producto y sucursal que realmente existe?

📖
The Data Warehouse Toolkit — Ralph Kimball & Margy Ross (Wiley, 3ª ed. 2013)
Ralph Kimball · Margy Ross
"Referential integrity requires that every foreign key in the fact table match a valid primary key in the associated dimension table. Orphaned foreign keys — fact rows that reference a non-existent dimension row — are among the most insidious data quality problems because they cause silent data loss in analytics queries."
🧒 Como para un niño de 8 años

Tu tabla de ventas dice "esta venta fue del cliente #9999". Pero cuando buscas en la lista de clientes, el #9999 no existe. Esa venta apunta a alguien que no está en el sistema — es como una carta con una dirección que no existe en el mapa. Cuando hagas el JOIN para el dashboard, esa venta aparecerá sin nombre de cliente, sin segmento, sin nada — como si no hubiera ocurrido.

def validar_fk(fact, dim, col_fk, nombre_dim, col_dim=None):
    """
    Valida que todos los valores de col_fk en fact
    existan en la dimensión correspondiente.
    Usa LEFT JOIN: las FKs huérfanas producen NaN en la dimensión.
    """
    if col_dim is None:
        col_dim = col_fk

    col_ref  = [c for c in dim.columns if c != col_dim][0]

    # LEFT JOIN: FK huérfana → col_ref queda NaN
    merged   = fact[[col_fk]].merge(
        dim[[col_dim, col_ref]],
        left_on=col_fk, right_on=col_dim, how='left'
    )
    huerfanas = merged[col_ref].isnull().sum()
    pct       = huerfanas / len(fact) * 100
    estado = "✅ OK" if huerfanas == 0 else f"⚠️  {huerfanas:,} FKs huérfanas ({pct:.2f}%)"
    print(f"  {col_fk:<18} → {nombre_dim:<20} {estado}")
    return huerfanas

print("VALIDACIÓN DE INTEGRIDAD REFERENCIAL — fact_ventas\n")
total = 0
total += validar_fk(fv, dim_clientes,   'id_cliente',  'dim_clientes')
total += validar_fk(fv, dim_productos,  'id_producto', 'dim_productos')
total += validar_fk(fv, dim_sucursales, 'id_sucursal', 'dim_sucursales')
total += validar_fk(fv, dim_tiempo,     'id_tiempo',   'dim_tiempo')
print(f"\n  Total FKs huérfanas: {total:,}")
fact[[col_fk]].merge(dim[...], how='left')LEFT JOIN entre fact_ventas (columna FK) y la dimensión. Si un id_cliente de ventas no existe en dim_clientes, la fila fusionada tendrá NaN en la columna de dimensión. Contar esos NaN = contar FKs huérfanas.
col_ref = [c for c in dim.columns if c != col_dim][0]Selecciona automáticamente la primera columna de la dimensión que no es la PK. Necesitamos alguna columna de la dimensión para detectar los NaN del JOIN.
def tratar_fk_huerfanas(fact, dim, col_fk, col_dim=None, accion='eliminar'):
    """
    accion='eliminar' → elimina filas huérfanas de fact
    accion='reportar' → solo reporta, no modifica
    """
    if col_dim is None: col_dim = col_fk
    ids_validos    = set(dim[col_dim].unique())
    mask_huerfanas = ~fv[col_fk].isin(ids_validos)
    n = mask_huerfanas.sum()

    if n == 0:
        print(f"  ✅ '{col_fk}' — sin FKs huérfanas")
        return fact
    if accion == 'eliminar':
        fact = fact[~mask_huerfanas].reset_index(drop=True)
        print(f"  ⚠️  '{col_fk}' — {n} filas eliminadas")
    return fact

fv = tratar_fk_huerfanas(fv, dim_clientes,   'id_cliente')
fv = tratar_fk_huerfanas(fv, dim_productos,  'id_producto')
fv = tratar_fk_huerfanas(fv, dim_sucursales, 'id_sucursal')
fv = tratar_fk_huerfanas(fv, dim_tiempo,     'id_tiempo')
ids_validos = set(dim[col_dim].unique())Crea un set (conjunto) con todos los IDs válidos de la dimensión. Usar set en vez de lista hace la búsqueda O(1) en vez de O(n) — en datasets grandes esto puede ser cientos de veces más rápido.
