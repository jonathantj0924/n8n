4. Outliers / Valores Atípicos

Qué son, por qué importan y cómo identificarlos

4.1 — ¿Qué es un outlier?

Un outlier (valor atípico) es una observación que se aleja significativamente del resto de los datos en una distribución. Antes de actuar, hay que distinguir qué tipo es:

🧒 Como para un niño de 8 años

Imagina que 30 niños del salón tienen entre 8 y 10 años. Si de repente uno tiene 35 años, eso es un outlier: un número que "no pega" con el resto. Pero ojo: puede ser un error (alguien escribió mal), o puede ser real (hay un adulto en el salón). ¡Tienes que averiguar cuál es antes de decidir qué hacer!

🐛
Tipo 1 — Outlier por Error

Es un error de captura, sistema o proceso. El dato está mal desde el origen.

Ejemplo del dataset: Una venta de $83,850.68 que debería ser ~$838. El sistema la multiplicó por 100 accidentalmente.

Decisión: Corregir o recortar (Winsorización).

🦄
Tipo 2 — Outlier Real (evento genuino)

El dato es correcto, solo que ese evento fue inusualmente extremo.

Ejemplo: Una empresa compró 200 unidades en una sola compra corporativa. Es raro, pero real.

Decisión: Conservar. Eliminarlo sesga el análisis.

🚨
Regla crítica del notebook: "Nunca elimines un outlier sin primero determinar si es un error o un evento real. Eliminar eventos reales extremos sesga el análisis y oculta información valiosa de negocio."
4.2

Métodos de detección de outliers

IQR de Tukey y Z-Score — los dos métodos del curso

Método 1 — Regla IQR (Criterio de Tukey) ← el que usamos

Desarrollado por John Tukey en 1977. Es el más usado en análisis exploratorio porque no asume ninguna distribución en los datos — funciona con casi cualquier dataset.

🧒 ¿Qué es el IQR en palabras simples?

Ordena todos tus datos de menor a mayor. El Q1 es el valor en el puesto 25% de la lista, el Q3 está en el puesto 75%. El IQR es la distancia entre ellos — básicamente la zona donde vive "la mitad normal" de tus datos. Si un valor está más allá de 1.5 veces esa distancia, se considera sospechoso.

Q1 = Percentil 25  |  Q3 = Percentil 75  |  IQR = Q3 − Q1

Límite inferior = Q1 − 1.5 × IQR
Límite superior = Q3 + 1.5 × IQR

Todo valor fuera de estos límites → candidato a outlier
💡
¿Por qué 1.5 y no otro número? Tukey demostró matemáticamente que con ese factor, en una distribución normal, solo el 0.7% de los datos quedan fuera — es decir, son genuinamente extremos. Algunos analistas usan 3.0 para detectar solo outliers muy severos (extremos extremos).

Método 2 — Puntaje Z (Z-Score)

Mide cuántas desviaciones estándar se aleja un valor de la media. Asume que los datos siguen una distribución normal (campana de Gauss).

🧒 ¿Qué mide el Z-Score?

Imagina que el promedio de estatura de tu clase es 1.30m. El Z-Score te dice: "este niño está a 3 estaturas promedio de distancia del promedio". Si esa distancia es mayor a 3, el valor es muy raro.

Z = (valor − media) / desviación estándar

Si |Z| > 3 → outlier (el 99.7% de los datos normales caben dentro de |Z| ≤ 3)

def detectar_outliers_iqr(df, columnas, factor=1.5):
    """
    Detecta outliers usando la Regla IQR de Tukey.
    Retorna un DataFrame con el resumen por columna.

    factor=1.5 → outliers moderados (Tukey estándar)
    factor=3.0 → outliers extremos (solo casos severos)
    """
    resultados = []

    for col in columnas:
        serie   = df[col].dropna()           # ignora nulos para el cálculo
        q1      = serie.quantile(0.25)
        q3      = serie.quantile(0.75)
        iqr     = q3 - q1
        lim_inf = q1 - factor * iqr          # límite por abajo
        lim_sup = q3 + factor * iqr          # límite por arriba

        # mask_out es True para cada fila que está fuera de los límites
        mask_out   = (df[col] < lim_inf) | (df[col] > lim_sup)
        n_outliers = mask_out.sum()          # cuántos outliers hay

        resultados.append({
            'columna'     : col,
            'Q1'          : round(q1, 2),
            'Q3'          : round(q3, 2),
            'IQR'         : round(iqr, 2),
            'lim_inferior': round(lim_inf, 2),
            'lim_superior': round(lim_sup, 2),
            'outliers'    : n_outliers,
            'pct_%'       : round(n_outliers / len(df) * 100, 3),
            'max_valor'   : round(df[col].max(), 2),
        })

    return pd.DataFrame(resultados).sort_values('outliers', ascending=False)

cols_numericas = ['total_venta', 'precio_unitario', 'precio_final',

5.2 — Decisión de tratamiento: Winsorización

No eliminamos filas — recortamos valores al límite permitido

📋
Contexto del dataset: Los outliers de total_venta fueron generados multiplicando valores por un factor de 8 a 15 — son errores de sistema. Con ese contexto, la decisión correcta es reemplazar con el límite superior. Esta técnica se llama Winsorización.
🧒 ¿Qué es la Winsorización?

Imagina que tienes una regla para medir de 0 a 30 cm. Alguien mide algo que da "500 cm" — claramente un error. En vez de tirar esa medición, la recortas al máximo de tu regla: 30 cm. La medición sigue existiendo, solo que con un valor razonable. Eso es Winsorizar: recortar al límite, no eliminar.

✂️
Winsorización ← lo que hacemos

Reemplazamos el valor extremo con el límite IQR. La fila de datos se conserva. No perdemos ninguna transacción.

🗑️
Eliminación ← lo que NO hacemos

Perdemos transacciones completas. Introduce sesgo en los análisis de volumen. El reporte diría que se vendió menos de lo que realmente se vendió.

def winsorizat_iqr(df, columna, factor=1.5):
    """
    Aplica Winsorización usando los límites IQR.
    Reemplaza valores fuera de los límites con el límite correspondiente.
    No elimina filas — preserva todas las transacciones.
    """
    q1      = df[columna].quantile(0.25)
    q3      = df[columna].quantile(0.75)
    iqr     = q3 - q1
    lim_inf = q1 - factor * iqr    # valores por debajo de esto → recortar aquí
    lim_sup = q3 + factor * iqr    # valores por encima de esto → recortar aquí

    # Contar cuántos valores serán recortados en cada extremo
    n_inf = (df[columna] < lim_inf).sum()
    n_sup = (df[columna] > lim_sup).sum()

    # .clip() es el corazón de la Winsorización:
    # lleva todos los valores al rango [lim_inf, lim_sup]
    # → si era más bajo que lim_inf, queda en lim_inf
    # → si era más alto que lim_sup, queda en lim_sup
    # → si estaba dentro, no cambia
    df[columna] = df[columna].clip(lower=lim_inf, upper=lim_sup)

    print(f"  '{columna}':")
    print(f"    Límite inferior : ${lim_inf:>10,.2f} → {n_inf} valores recortados")
    print(f"    Límite superior : ${lim_sup:>10,.2f} → {n_sup} valores recortados")
    print(f"    Nuevo máximo    : ${df[columna].max():>10,.2f}")
    print(f"    Nueva media     : ${df[columna].mean():>10,.2f}")
    return df

print("WINSORIZACIÓN — Tratamiento de outliers\n")
fv = winsorizat_iqr(fv, 'total_venta')

n_inf = (df[columna] < lim_inf).sum()Cuenta cuántos valores están por debajo del límite inferior (para reportar cuántos se recortaron).

def estandarizar_valores(df, columna, mapa_reemplazos):
    """
    Reemplaza valores inconsistentes según un mapa de equivalencias.
    El mapa lo define el analista con conocimiento de negocio.

    mapa_reemplazos: dict {'valor_incorrecto': 'valor_correcto'}
    """
    n_antes  = df[columna].nunique()   # cuántos valores únicos hay antes

    # Para cada valor: si está en el mapa, reemplázalo;
    # si no está, mantenlo igual; si es nulo, déjalo nulo
    cambios  = df[columna].map(
        lambda x: mapa_reemplazos.get(x, x) if pd.notna(x) else x
    )
    n_cambios = (df[columna] != cambios).sum()  # cuántas filas cambiaron
    df[columna] = cambios
    n_despues = df[columna].nunique()  # cuántos únicos quedan después

    print(f"  '{columna}':")
    print(f"    Valores únicos antes  : {n_antes}")
    print(f"    Valores únicos después: {n_despues}")
    print(f"    Registros modificados : {n_cambios:,}")
    return df

6.2 — ¿Qué es un duplicado? Detección y eliminación

Los 3 tipos de duplicados y cómo eliminarlos correctamente

Hay 3 tipos de duplicados en datos transaccionales:

🔴
Duplicado exacto

Todas las columnas son idénticas. Mismo ID, mismo valor, mismo todo. Claramente un error.

🟡
Duplicado de clave

El ID es el mismo pero algún campo varía. Más difícil de detectar. Requiere investigar cuál es el correcto.

🟢
Duplicado de negocio

Diferentes IDs pero misma transacción real procesada dos veces por el sistema.

🧒 Como para un niño de 8 años

Imagina que en tu lista de compras escribiste "manzanas" dos veces. Si vas al mercado y compras "manzanas" dos veces, gastás el doble de lo que debías. Los duplicados en datos hacen lo mismo: hacen que cuentes la misma venta dos veces, inflando tus ingresos reportados.

6.3 — Violación de dominio

El valor existe y no es nulo, pero está fuera de los valores válidos

🧒 Como para un niño de 8 años

Imagina una pregunta de examen donde puedes elegir A, B, C o D. Si alguien contesta "E", esa respuesta existe, no está en blanco, pero no es una opción válida. Eso es una violación de dominio: el valor existe pero no pertenece al conjunto de opciones permitidas.

# Validación de dominio — valores permitidos por columna
dominios = {
    'region' : ['Costa', 'Sierra', 'Digital'],
    'tipo'   : ['Mall', 'Tienda grande', 'Tienda mediana', 'Digital', 'Híbrido'],
}

print("VALIDACIÓN DE DOMINIO — dim_sucursales\n")
for col, valores_validos in dominios.items():
    # ~ significa "NOT" — encuentra las filas que NO están en la lista válida
    mask_invalidos = ~dim_sucursales[col].isin(valores_validos)
    n = mask_invalidos.sum()

    if n > 0:
        print(f"  ⚠️  '{col}' — {n} valor(es) fuera de dominio:")
        print(dim_sucursales[mask_invalidos][['id_sucursal','nombre','ciudad','provincia',col]])
    else:
        print(f"  ✅ '{col}' — todos los valores dentro del dominio")

7. Integridad Referencial y JOINs de Validación

¿Cada venta apunta a un cliente, producto y sucursal que existen?

7.1 — ¿Qué es la integridad referencial?

En el esquema estrella, cada FK (clave foránea) en fact_ventas debe apuntar a un registro que existe en la dimensión correspondiente. Cuando esto no ocurre, hay una FK huérfana.

🧒 Como para un niño de 8 años

Imagina que tu tabla de ventas dice "esta venta fue hecha por el cliente número 9999". Pero cuando vas a la tabla de clientes, el número 9999 no existe. Esa venta "apunta" a alguien que no existe en el sistema — eso es una FK huérfana. Es como si una carta tuviera una dirección que no existe en el mapa.

💀
Consecuencias de FKs huérfanas:
  • Los JOIN con dimensiones producen filas con NaN en todas las columnas de la dimensión
  • Los KPIs "por segmento de cliente" o "por categoría de producto" omiten esas ventas silenciosamente
  • Los dashboards muestran totales menores a los reales

7.2 — Tipos de JOIN y su relación con integridad referencial

Tipo de JOIN¿Qué hace?FK huérfana produce
INNER JOINSolo filas que existen en AMBAS tablasLa fila desaparece del resultado
LEFT JOIN ← usamosTodas las filas de la izquierda, NaN si no hay matchNaN en columnas de la dimensión
FULL JOINTodas las filas de ambas tablasNaN en los dos lados
# Función para validar integridad referencial de una FK
def validar_fk(fact, dim, col_fk, nombre_dim, col_dim=None):
    """
    Valida que todos los valores de col_fk en fact
    existan en la dimensión correspondiente.

    Usa LEFT JOIN: las FKs huérfanas producen NaN
    en la columna de la dimensión.
    """
    if col_dim is None:
        col_dim = col_fk  # mismo nombre en ambas tablas

    # Tomar cualquier columna de la dimensión que no sea la PK
    col_ref = [c for c in dim.columns if c != col_dim][0]

    # LEFT JOIN: si la FK no existe en dim → col_ref queda como NaN
    merged   = fact[[col_fk]].merge(
        dim[[col_dim, col_ref]],
        left_on  = col_fk,
        right_on = col_dim,
        how      = 'left'
    )
    huerfanas = merged[col_ref].isnull().sum()  # NaN = FK huérfana
    pct       = huerfanas / len(fact) * 100

    estado = "✅ OK" if huerfanas == 0 else f"⚠️  {huerfanas:,} FKs huérfanas ({pct:.2f}%)"
    print(f"  {col_fk:<18} → {nombre_dim:<20} {estado}")
    return huerfanas

print("VALIDACIÓN DE INTEGRIDAD REFERENCIAL — fact_ventas\n")
total_huerfanas  = 0
total_huerfanas += validar_fk(fv, dim_clientes,   'id_cliente',  'dim_clientes')
total_huerfanas += validar_fk(fv, dim_productos,  'id_producto', 'dim_productos')
total_huerfanas += validar_fk(fv, dim_sucursales, 'id_sucursal', 'dim_sucursales')
total_huerfanas += validar_fk(fv, dim_tiempo,     'id_tiempo',   'dim_tiempo')
print(f"\n  Total FKs huérfanas: {total_huerfanas:,}")
fact[[col_fk]].merge(dim[...], left_on=col_fk, right_on=col_dim, how='left')Hace un LEFT JOIN entre fact_ventas (solo la columna FK) y la dimensión. Si un id_cliente de fact_ventas no existe en dim_clientes, la fila fusionada tendrá NaN en la columna de la dimensión.
merged[col_ref].isnull().sum()Cuenta los NaN resultantes del JOIN. Cada NaN representa una FK huérfana — una venta que apunta a un cliente/producto/sucursal inexistente.
col_ref = [c for c in dim.columns if c != col_dim][0]Toma automáticamente la primera columna de la dimensión que no es la clave primaria. La necesitamos para detectar los NaN del JOIN.

Tratamiento de FKs huérfanas

def tratar_fk_huerfanas(fact, dim, col_fk, col_dim=None, accion='eliminar'):
    """
    Trata filas con FKs huérfanas.

    accion='eliminar' → elimina las filas huérfanas de fact
    accion='reportar' → solo reporta, no modifica
    """
    if col_dim is None:
        col_dim = col_fk

    ids_validos    = set(dim[col_dim].unique())       # IDs que SÍ existen
    mask_huerfanas = ~fv[col_fk].isin(ids_validos)    # filas con ID inválido
    n = mask_huerfanas.sum()

    if n == 0:
        print(f"  ✅ '{col_fk}' — sin FKs huérfanas")
        return fact

    if accion == 'eliminar':
        fact = fact[~mask_huerfanas].reset_index(drop=True)
        print(f"  ⚠️  '{col_fk}' — {n} filas huérfanas eliminadas")
    else:
        print(f"  ⚠️  '{col_fk}' — {n} filas huérfanas (solo reporte)")

    return fact

print("TRATAMIENTO DE FKs HUÉRFANAS\n")
fv = tratar_fk_huerfanas(fv, dim_clientes,   'id_cliente')
fv = tratar_fk_huerfanas(fv, dim_productos,  'id_producto')
fv = tratar_fk_huerfanas(fv, dim_sucursales, 'id_sucursal')
fv = tratar_fk_huerfanas(fv, dim_tiempo,     'id_tiempo')

print(f"\n  Filas restantes: {len(fv):,}")
ids_validos = set(dim[col_dim].unique())Crea un conjunto con todos los IDs que existen en la dimensión. Usar set() hace la búsqueda mucho más rápida que una lista cuando el dataset es grande.
~fv[col_fk].isin(ids_validos)Para cada fila de fact_ventas, verifica si el ID está en la lista de IDs válidos. El ~ invierte: True para los que NO están (los huérfanos).
fact = fact[~mask_huerfanas].reset_index(drop=True)Elimina las filas huérfanas y renumera el índice. Solo ocurre si accion='eliminar'.
