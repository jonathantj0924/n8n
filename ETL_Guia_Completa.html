¿Qué es ETL y por qué existe?

La base de toda Inteligencia de Negocios

ETL son las siglas de Extract (Extraer) → Transform (Transformar) → Load (Cargar). Es el proceso por el cual los datos pasan de sus fuentes originales (bases de datos, Excel, APIs) a un estado limpio y utilizable para análisis y toma de decisiones.

🧒 Explicado como para un niño de 8 años

Imagina que tienes una caja llena de LEGO de miles de colores mezclados, sucios, con algunas piezas rotas y otras repetidas. El ETL es el proceso de sacar los LEGO de la caja (Extract), lavarlos, ordenarlos por color y separar los rotos (Transform), y guardarlos ordenados en cajitas etiquetadas (Load) para que cuando quieras construir algo, todo esté listo y limpio.

📤
EXTRACT — Extraer

Leer los datos desde la fuente original sin tocarlos ni modificarlos. Solo observar.

🔧
TRANSFORM — Transformar

Limpiar, corregir, estandarizar y enriquecer los datos para que sean confiables.

📥
LOAD — Cargar

Guardar los datos limpios en el destino final (Data Warehouse, base de datos, archivo).

¿Por qué es la fase más crítica del BI?

🗑️
"Garbage in, garbage out." Si los datos están sucios cuando entran, el análisis y los reportes también estarán sucios. Un KPI calculado sobre datos incorrectos lleva a decisiones de negocio equivocadas.

Consecuencias reales de saltarse el ETL:

  • 📈 Un KPI de ventas inflado por registros duplicados
  • 💸 Un promedio de ticket distorsionado por valores atípicos no detectados
  • 👥 Una segmentación de clientes incorrecta por nulos mal tratados
  • ❌ Decisiones de negocio tomadas sobre información falsa

Los 6 problemas de calidad de datos que atacamos

🔢
Tipos incorrectos

Una fecha guardada como texto, o un número guardado como texto. El sistema no puede operar con ellos correctamente.

🕳️
Valores nulos (vacíos)

Celdas sin información. Según la causa, se tratan de forma diferente.

📋
Duplicados

La misma fila (o casi) aparece más de una vez. Inflan conteos y promedios.

🔤
Inconsistencias de texto

"Efectivo" vs "efectivo" vs "EFECTIVO" — el sistema los ve como 3 cosas diferentes.

🚀
Outliers (valores atípicos)

Valores extremadamente altos o bajos que distorsionan estadísticas y modelos.

🚫
Violación de dominio

Un valor que existe y no es nulo, pero es imposible en el contexto real (ej: cantidad = -5 productos).

⭐

La Regla de Oro del ETL

La regla más importante antes de tocar cualquier archivo

✅
Nunca modifiques el archivo original. Siempre trabajamos sobre una copia y guardamos el resultado con un nombre nuevo. El archivo BIZDATA_dataset_maestro_retail.xlsx nunca se toca.

Paso 1 — Auditoría de los Datos Sesión 2

Diagnosticar antes de operar. Nunca asumas — verifica.

Antes de cambiar cualquier cosa, necesitamos conocer el estado real de los datos. La auditoría es como hacerle un chequeo médico a los datos: revisamos todo para saber qué está bien y qué necesita tratamiento.

🧒 Explicado como para un niño de 8 años

Imagina que alguien te da una mochila llena de ropa para lavar. Antes de meterla a la lavadora, revisas pieza por pieza: ¿hay algo blanco entre la ropa de color? ¿Hay algo que no debe mojarse? ¿Hay piezas que ya están sucias de una manera especial? La auditoría es esa revisión inicial.

1.1 — Auditoría Inicial

Generamos un reporte completo de calidad sobre el DataFrame principal. Esta función no modifica nada — solo describe el estado actual.

def auditar_dataframe(df, nombre):
    """Reporte de calidad completo. No modifica datos, solo describe."""
    print("=" * 60)
    print(f"  REPORTE DE AUDITORÍA — {nombre}")
    print("=" * 60)
    print(f"\n  Dimensiones : {df.shape[0]:,} filas × {df.shape[1]} columnas")
    print(f"  Memoria     : {df.memory_usage(deep=True).sum() / 1024**2:.2f} MB")

    print("\n  ── TIPOS DE DATOS ──")
    for col in df.columns:
        dtype   = str(df[col].dtype)
        nulos   = df[col].isnull().sum()       # cuántos vacíos
        pct     = nulos / len(df) * 100       # porcentaje de vacíos
        unicos  = df[col].nunique()            # cuántos valores distintos
        flag    = " ⚠️" if nulos > 0 else ""  # marcar si hay nulos
        print(f"  {col:<22} {dtype:<12} nulos:{nulos:>5} ({pct:>4.1f}%) únicos:{unicos:>6}{flag}")

    print("\n  ── DUPLICADOS ──")
    dups = df.duplicated().sum()
    print(f"  Filas duplicadas: {dups:,} ({dups/len(df)*100:.2f}%)")

    print("\n  ── ESTADÍSTICAS NUMÉRICAS ──")
    print(df.select_dtypes(include='number').describe().round(2).to_string())

1.3 — Auditoría de Rangos Numéricos

Un dato puede ser técnicamente válido (no nulo, tipo correcto) pero contextualmente imposible. Por ejemplo: ¿puede haber una cantidad de -5 productos vendidos? ¿Un precio de $0?

def auditar_rangos(df, columnas_reglas):
    """
    Verifica si los valores numéricos están dentro de rangos esperados.
    Las reglas de negocio las DEFINES TÚ — no el sistema.
    """
    for col, (minimo, maximo) in columnas_reglas.items():
        fuera  = df[(df[col] < minimo) | (df[col] > maximo)]
        estado = "⚠️  REVISAR" if len(fuera) > 0 else "✅ OK"
        print(f"  {col}: rango esperado [{minimo} – {maximo}] | fuera: {len(fuera):,} filas  {estado}")

auditar_rangos(fv, reglas)

¿Por qué importan los tipos de datos?

Pandas asigna tipos automáticamente al leer un archivo. Pero "automático" no significa "correcto". Un tipo incorrecto significa que no puedes hacer operaciones con esa columna.

🧒 Explicado como para un niño de 8 años

Imagina que tienes una caja con números escritos en papel, pero alguien los escribió con letras: "cinco", "diez", "tres". Python no puede sumar esos números porque para él son palabras, no números. Hay que convertirlos a formato número primero.

Paso 3 — Tratamiento de Valores Nulos Sesión 2

Los datos faltantes no son todos iguales — primero entender, luego decidir

Un valor nulo (o NaN — "Not a Number") es una celda vacía. Pero no todos los nulos son iguales: la causa del nulo determina cómo tratarlo.

🧒 Explicado como para un niño de 8 años

Imagina que en una lista de asistencia hay varios nombres en blanco. ¿Por qué están en blanco? Puede ser porque: 1) el maestro olvidó escribirlos al azar, 2) los estudiantes que faltan más son precisamente los que pagan menos, 3) el alumno se fue antes de que pasaran lista. Cada causa tiene una solución diferente — no puedes tratarlos todos igual.

3.1 — Los 3 mecanismos de ausencia de datos

🎲
MCAR

Missing Completely At Random
El dato falta por pura casualidad, sin relación con ninguna variable.

Ejemplo: El sistema tuvo un corte de luz de 2 min y no registró el método de pago de 15 transacciones al azar.

Acción: Se puede eliminar o imputar sin sesgar el análisis.

🔗
MAR

Missing At Random
El dato falta de forma relacionada con otras variables observadas.

Ejemplo: Los clientes que pagan en efectivo tienden a no registrar el canal de venta.

Acción: Imputar usando las otras variables como predictores.

🎭
MNAR

Missing Not At Random
El dato falta por razones relacionadas con el propio valor no observado.

Ejemplo: Clientes con transacciones muy altas no registran el método de pago intencionalmente.

Acción: No hay solución estadística perfecta. Requiere criterio de negocio.

💡
Regla pragmática: En el 80% de los casos no sabrás con certeza el mecanismo. Si el porcentaje de nulos es <5% y no hay patrón visible → imputar con moda o mediana. Si es >10% → investigar antes de decidir.

3.2 — Técnicas de imputación

Imputar significa "rellenar" los valores faltantes con un valor calculado o inferido.

🔤
Para columnas de texto (categóricas)
  • Moda: reemplazar con el valor más frecuente
  • "Desconocido": cuando no se puede inferir
  • Condicional: la moda dentro de un grupo
🔢
Para columnas numéricas
  • Media: solo si distribución es simétrica (sin outliers)
  • Mediana: cuando hay outliers ← más robusta
  • Por grupo: media/mediana dentro de un segmento
⚠️
Advertencia estadística: Imputar con la media en presencia de outliers introduce sesgo. Siempre usa la mediana cuando hay valores extremos.

3.3 — Código de tratamiento de nulos

# 1. Identificar nulos por columna

reporte_pct   = reporte_nulos / len(fv) * 100

        print(f"  ⚠️  {col:<22} {n:>6,} nulos ({pct:.1f}%)")

# ─────────────────────────────────────────────────────────────
# 2. Imputar columnas categóricas con la MODA

Paso 4 — Outliers (Valores Atípicos) Sesión 3

Detectar y decidir qué hacer con valores extremos

¿Qué es un outlier?

Un outlier (valor atípico) es una observación que se aleja significativamente del resto de los datos. Existen dos tipos fundamentales:

🧒 Explicado como para un niño de 8 años

Imagina que mides la estatura de 30 niños de tu salón. La mayoría mide entre 1.20 m y 1.40 m. De repente aparece alguien que mide 3 metros. Ese valor raro y extremo es un outlier. Puede ser que alguien escribió mal el número (un error), o puede ser que realmente hay un niño inusualmente alto (un evento real). ¡Tienes que averiguar cuál es antes de decidir qué hacer!

🐛
Outlier por Error

Es un error de captura, sistema o proceso. Debe corregirse.

Ejemplo: Una venta de $83,850 que debería ser $838.50 — el sistema multiplicó por 100 por error.

🦄
Outlier Real (Evento Real)

Es un evento genuinamente extremo. No debe eliminarse.

Ejemplo: Una empresa compró 500 unidades de un producto en una sola compra corporativa.

🚨
Regla crítica: Nunca elimines un outlier sin primero determinar si es un error o un evento real. Eliminar eventos reales extremos sesga el análisis y oculta información valiosa de negocio.

4.1 — ¿Por qué los outliers son un problema?

Los outliers distorsionan las estadísticas descriptivas. Veamos el impacto real en los datos del dataset:

4.2 — Métodos de detección

Método 1 — Regla IQR (Criterio de Tukey) ← el más usado

No asume ninguna distribución en los datos. Funciona bien con casi cualquier dataset.

Q1 = Percentil 25  |  Q3 = Percentil 75  |  IQR = Q3 − Q1

Límite inferior = Q1 − 1.5 × IQR
Límite superior = Q3 + 1.5 × IQR

Todo valor fuera de estos límites → candidato a outlier
🧒 ¿Qué es el IQR en palabras simples?

Si ordenas todos tus datos de menor a mayor, el Q1 es el valor que queda en el 25% de la lista, y el Q3 queda en el 75%. El IQR es la distancia entre ellos — la zona donde está "la mayoría normal" de tus datos. Cualquier cosa más allá de 1.5 veces esa distancia empieza a considerarse sospechosa.

Método 2 — Z-Score (Puntaje Z)

Mide cuántas desviaciones estándar se aleja un valor de la media. Asume distribución normal.

Z = (valor − media) / desviación estándar

Si |Z| > 3 → outlier (cubre el 99.7% de una distribución normal)

4.3 — Código de detección de outliers

def detectar_outliers_iqr(df, columnas, factor=1.5):
    """
    Detecta outliers usando la Regla IQR de Tukey.
    factor=1.5 → outliers moderados (estándar)
    factor=3.0 → solo outliers muy extremos
    """
    resultados = []
    for col in columnas:
        serie   = df[col].dropna()
        q1      = serie.quantile(0.25)
        q3      = serie.quantile(0.75)
        iqr     = q3 - q1
        lim_inf = q1 - factor * iqr
        lim_sup = q3 + factor * iqr

        mask_out   = (df[col] < lim_inf) | (df[col] > lim_sup)
        n_outliers = mask_out.sum()

        resultados.append({
            'columna'     : col,
            'Q1'          : round(q1, 2),
            'Q3'          : round(q3, 2),
            'lim_inferior': round(lim_inf, 2),
            'lim_superior': round(lim_sup, 2),
            'outliers'    : n_outliers,
            'pct_%'       : round(n_outliers / len(df) * 100, 3),
        })
    return pd.DataFrame(resultados).sort_values('outliers', ascending=False)

cols_numericas = ['total_venta', 'precio_unitario', 'precio_final',
                  'costo_total', 'margen_usd', 'cantidad', 'descuento_pct']

reporte_outliers = detectar_outliers_iqr(fv, cols_numericas)
print(reporte_outliers.to_string(index=False))

4.4 — Tratamiento: Winsorización

En nuestro dataset, los outliers de total_venta fueron errores de sistema (valores multiplicados por 8 a 15 veces). La decisión correcta es Winsorización: no eliminamos la fila, solo "recortamos" el valor al límite estadísticamente aceptable.

🧒 ¿Qué es la Winsorización?

Imagina que tienes una regla para medir cosas, pero algunas medidas salen del borde de la regla. En vez de tirar esas medidas, las ajustas al borde máximo de la regla. La fila de datos sigue existiendo, solo que su valor extremo queda recortado al límite permitido.

✂️
Winsorización ← lo que hacemos

Reemplazamos el valor extremo con el límite superior/inferior del IQR. La fila se conserva.

🗑️
Eliminación ← lo que NO hacemos (en este caso)

Perdemos información transaccional completa. Introduce sesgo en los análisis de volumen.

def winsorizat_iqr(df, columna, factor=1.5):
    """
    Aplica Winsorización usando los límites IQR.
    Reemplaza valores fuera de los límites con el límite correspondiente.
    No elimina filas — preserva todas las transacciones.
    """
    q1      = df[columna].quantile(0.25)
    q3      = df[columna].quantile(0.75)
    iqr     = q3 - q1
    lim_inf = q1 - factor * iqr
    lim_sup = q3 + factor * iqr

    n_inf   = (df[columna] < lim_inf).sum()
    n_sup   = (df[columna] > lim_sup).sum()

    # .clip() es el corazón de la Winsorización:
    # lleva todos los valores al rango [lim_inf, lim_sup]
    df[columna] = df[columna].clip(lower=lim_inf, upper=lim_sup)

    print(f"'{columna}': {n_inf} valores recortados (abajo), {n_sup} recortados (arriba)")
    print(f"Nuevo máximo: ${df[columna].max():,.2f}")
    return df

fv = winsorizat_iqr(fv, 'total_venta')

Paso 5 — Detección y Eliminación de Duplicados Sesión 3

Registros repetidos que inflan los conteos y promedios

¿Qué es un duplicado?

Un duplicado es una fila que aparece más de una vez en la tabla. Existen 3 tipos en datos transaccionales:

🔴
Duplicado exacto

Todas las columnas son idénticas. Claramente un error de sistema.

🟡
Duplicado de clave

El ID es el mismo pero algún campo varía ligeramente. Más difícil de detectar.

🟢
Duplicado de negocio

Diferentes IDs pero misma transacción real (ej: misma compra procesada dos veces).

🧒 Explicado como para un niño de 8 años

Imagina que tienes una lista de los alumnos de tu clase y el mismo nombre aparece dos veces. Si cuentas los alumnos usando esa lista, vas a creer que hay más de los que realmente hay. Los duplicados hacen lo mismo con las ventas: te hacen creer que vendiste más de lo que realmente vendiste.

⚠️
Primero estandarizar texto, luego buscar duplicados. Los duplicados a veces tienen inconsistencias de texto que los hacen parecer distintos cuando son el mismo registro. "efectivo" ≠ "Efectivo" para el sistema, aunque para nosotros sean lo mismo.

Paso 6 — Estandarización Profunda de Texto Sesión 3

Unificar valores que representan lo mismo pero están escritos diferente

En la Sesión 2 corregimos capitalización superficialmente (mayúsculas/minúsculas). Ahora atacamos las inconsistencias semánticas: valores que significan lo mismo pero están escritos diferente.

🧒 Explicado como para un niño de 8 años

Imagina que tienes una lista de métodos de pago y ves: "T.Debito", "Tarjeta Debito", "Tarjeta Débito". Para nosotros los humanos, los tres significan lo mismo. Pero para la computadora, son 3 cosas completamente diferentes. Si haces un gráfico de pagos, aparecerán como 3 barras distintas en vez de una sola. Tenemos que decirle a la computadora que todas son la misma cosa.

6.1 — Estandarización con mapas de equivalencias

def estandarizar_valores(df, columna, mapa_reemplazos):
    """
    Reemplaza valores inconsistentes según un mapa de equivalencias.
    El mapa lo define el analista con conocimiento de negocio.
    """
    cambios = df[columna].map(
        lambda x: mapa_reemplazos.get(x, x) if pd.notna(x) else x
    )
    n_cambios = (df[columna] != cambios).sum()
    df[columna] = cambios
    print(f"  '{columna}': {n_cambios:,} registros modificados")
    return df

6.2 — Violación de dominio

El valor existe, no es nulo, no es duplicado, pero está fuera del conjunto de valores válidos para esa columna.

🚨
Ejemplo: La columna devolucion solo puede tener valores 0 o 1 (sí devolvió / no devolvió). Si encuentras un valor "2" o "-1", eso es una violación de dominio. El valor existe, no es nulo, pero es imposible en el contexto del negocio. 
# Verificar violaciones de dominio en 'devolucion' (solo puede ser 0 o 1)
valores_validos_dev = {0, 1}
violaciones = fv[~fv['devolucion'].isin(valores_validos_dev)]

if len(violaciones) > 0:
    print(f"⚠️  {len(violaciones)} violaciones de dominio en 'devolucion'")
    print(violaciones['devolucion'].value_counts())
else:
    print("✅ Sin violaciones de dominio en 'devolucion'")
